# Navia V3 Chat + Know 总验收计划

状态：`DOCUMENT CANDIDATE / IMPLEMENTATION NO-GO`

继承原则：既有 V3-2..V3-7 自动门槛、12 页 B站单 run 与 H01-H10 全部保留。本计划只追加 Runtime/Chat/Know 验收，不替换原样本、不改写原编号、不用新增通过抵消旧失败。

## 1. 总出门场景

### G1 手动本机服务

场景：新用户完成一次安装和配对。  
操作：点击桌面 Navia 图标启动；打开扩展；在设置查看状态；停止并重新启动。  
门槛：扩展不自动拉起进程；状态变化真实；首次配对后无需重复输入 token；停止前提示任务影响；秘密扫描 0 命中。

### G2 当前网页 Chat

场景：用户阅读真实文章或技术文档。  
操作：读取当前页；查看来源；提问；生成摘要；点击来源反跳。  
门槛：正文来自当前页；回答引用可定位；页面变化能失效旧上下文；无正文时 fail closed。

### G3 B站视频 Chat

场景：用户打开冻结 B站样本。  
操作：授权并开始分析；观察字幕/媒体/ASR 路线；查看时间线；点击时间点。  
门槛：使用真实页面和当前登录态；字幕、SenseVoice 和可信 capture 按合同降级；跳转时间有效；临时件和凭据清理为 0 残留。

### G4 知识提取

场景：用户从当前上下文提取知识。  
操作：点击提取；编辑草稿；取消一次；再次提取并确认保存。  
门槛：取消不落库；保存前清楚显示来源和目标字段；保存后生成唯一 item；模型不能绕过确认写库。

### G5 Know 管理

场景：用户管理已保存条目。  
操作：在 Know 搜索/排序；编辑标题、标签、备注；标记 aging；归档；重启后复查；返回来源。  
门槛：全部数据来自真实本地存储；重启前后一致；来源可打开；无 Mock badge 或伪成功；普通删除不宣称 Durable Forget。

### G6 信息架构

场景：用户在生产构建中切换主要功能。  
操作：切换 Chat/Know，打开 Settings。  
门槛：一级导航只有 Chat/Know；Settings 是辅助入口；Agent/Debug 不作为生产一级入口；各视口无文本截断或 incoherent overlap。

## 2. 自动化门槛

- Schema/contract meta validation 全部通过，固定负例逐项命中唯一 failure code。
- 单元、集成、带参白盒、冒烟和真实 Chrome 流程均有独立结果；不得只引用旧日志。
- 360、420、768、1280 四视口；Axe serious/critical=0；键盘主流程通过。
- 普通网页与 B站真实数据必须在同一 production candidate build 验证。
- 所有终态经过 cleanup barrier；公开包 secret/path/profile 扫描 0 命中。
- PRD 检视必须逐项回答 Chat、Know、Runtime、Agent 延后和 V4 边界，没有 N/A。

## 3. 人工最小步骤

1. 从桌面图标启动本机服务，确认设置页显示已连接。
2. 在一个真实网页完成读取、提问、来源反跳。
3. 在一个冻结 B站样本完成分析并点击时间点。
4. 从 Chat 提取草稿，先取消，再保存。
5. 在 Know 编辑、排序、归档并返回来源。
6. 停止 Runtime，确认 Chat/Know 显示可恢复的离线状态而非 Mock 成功。

人工只判断可理解性、操作负担、视觉结果和内容可信度；机器合同、ASR 听写、secret scan 和清理计数不得转嫁给人类。

## 4. No-Go

- Runtime 自动启动或关闭浏览器即强制销毁。
- 任一产品路径仍使用 Mock 数据却显示成功。
- Agent 出现在 V3 出门承诺。
- 知识未经确认自动保存。
- 仅媒体能力通过就声明 Chat/Know 全链通过。
- Query、Graph、Durable Forget、自动老化被计入 V3 PASS。
- 删除、重编号或用新增网页/知识样本替换原 V3-0..V3-7 分母与 H01-H10。
