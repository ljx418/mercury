体验差异

维度当前 blockedWP-B
下一步只有重复自动分析一个明确的“选择本地视频”动作
透明度用户不知道为什么无结果说明自动获取失败、本地处理、不会云上传

最小用户路线

1 自动路线字幕、受控下载、本地 ASR 按既有顺序执行。
2 诚实受阻三条自动输入均失败，不静默启动 tabCapture。
3 显式选择用户选择当前视频的单个 MP4/WebM/MKV 文件。
4 本机准备流式写入、SHA-256、ffprobe、音频和选帧交接。
5 内容生成复用 SenseVoice、OCR、图文大纲、时间线与导图。
6 清理完成双消费者收据闭合后清零共享输入，只保留允许的派生证据。

恢复原则

取消

立即中断浏览器传输和 Runtime worker，删除 staging，保留当前页面任务可重新选择。

Runtime 重启

SQLite 保留失败状态；不恢复 File 权限，校验 manifests 后清理并要求重选。

页面切换

导入绑定原 task/source identity。切换到另一视频不得把旧文件附着到新任务。

目标架构

架构显式包含持久 import store、acquisition/visual 双沙箱、consumer barrier、ASR 与视觉消费者；既有 SourceAuthority 继续权威。

出门条件

范围必须证明
合同exact Origin、bearer、一次性 token、SQLite 状态单调、18 码闭集。
文件边界合法大 ASGI chunk 内切、2 GiB+1、伪装容器、损坏媒体、4h+1 均 fail closed。
真实数据100 MB 与 1 GB 私有真实有声动态视频走公开路径，产生真实转写与截图。
生命周期双消费者 barrier、hard kill、重启 GET、取消与磁盘不足后双沙箱残留为 0。
体验一次选择、真实进度、可取消、错误有下一步；键盘/ARIA/滚动可用且无声音。
隐私原始媒体不进 Provider/日志/证据；文件名只在 Extension DOM，路径不出现在请求/store。

WP-B 完成不等于 V3 全阶段 PASS，也不自动恢复 tabCapture。WP-C 仍为可选、默认关闭的重新资格化工作包。
