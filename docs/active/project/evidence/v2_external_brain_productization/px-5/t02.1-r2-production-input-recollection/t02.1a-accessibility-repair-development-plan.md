# T02.1a Workspace Source Detail 可访问性修复开发计划

## 1. 用户目标

在不改变 Workspace 信息架构、布局、组件行为和状态合同的前提下，使 Source Detail 的
辅助标签和 Evidence 说明文字达到 WCAG AA 普通文本 4.5:1 对比度，并让真实 Axe 扫描
`serious=0`、`critical=0`。

## 2. 修改范围

唯一产品文件：

```text
apps/chrome-extension/entrypoints/workspace/style.css
```

计划修改：

```text
.source-facts dt
  #71807b -> #596965

.evidence-summary p
  #667570 -> #596965
```

`#596965` 对 `#f3f6f5` 的 sRGB 对比度约为 `5.32:1`，为 11px/12px 普通文本保留高于
4.5:1 的余量。颜色复用现有 `.service-strip span`，不引入新主题 token。

## 3. 明确不改

- 不改 React 组件树、文本、ARIA、焦点或路由。
- 不改 Runtime、Adapter、data_service、source 生命周期或任何 API。
- 不改 Axe 配置、影响级别、规则集或验收阈值。
- 不改 Side Panel 样式。
- 不借机重构 Workspace CSS 或设计 token。

## 4. 执行顺序

1. 修改两条 CSS 颜色声明。
2. 静态计算两组 foreground/background 对比度，要求均不低于 4.5:1。
3. 执行 extension build、typecheck、collector tests、frontend full tests。
4. 执行针对真实 Workspace Source Detail 的 Axe 与键盘检查。
5. 重新执行 T01 真实 Chrome 36 项回归。
6. 创建新的完整 T02.1 production-input run；不得复用历史 run artifact。
7. 执行 T02-A01..A12、T02.1-A01..A12、T03 input-readiness 和 PRD 规格检视。
8. 生成候选验收与独立审计包；独立复审前 T03 仍保持 No-Go。

## 5. 回滚与停止

出现以下任一情况立即停止并回到计划：

- Axe 仍有 serious/critical，或新增其他 violation。
- 视觉核查出现信息层级退化、文字难读或状态含义变化。
- 键盘、T01、前端或 Runtime 回归失败。
- 新 run 不能独立满足 12 source、route recovery、typed Axe/Keyboard 或 seal。
- 需要修改两条 CSS 之外的产品行为才能通过。
