# T04.1 Replay ArtifactRoot 一致性修复开发计划

日期：2026-09-14  
状态：`DOCUMENT REMEDIATION CANDIDATE / IMPLEMENTATION NO-GO`

## 1. 问题与目标

T04 独立实现出门审计授予 LIMITED PASS，同时记录一个 PX-6 前置 Minor：`replayLane.actualInvocation.artifactRoot=replay_validation`，其 `steps[*]` 内 ArtifactRef 却使用 `validation_run`。二者当前解析到同一物理目录，但命名不一致会让 PX-6 reader 被迫实现别名判断。

T04.1 只消除该命名歧义，不改变产品、T03 语义、比较算法、证据分母或人类边界。T03 原始 `invocation-record.json` 必须保持 `validation_run`，继续用于 R4-P 确定性比较；T04.1 另行派生 `resolved-invocation-record.json`，其根引用及内部 step implementation/stdout/stderr/productionPackage 引用全部使用 `replay_validation`。`replayLane.actualInvocation` 只允许引用该派生记录。

派生记录使用 `v2-px-replay-invocation-record/v1` 合同和 `artifact_root_rebase_validation_to_replay_v1` 算法。算法只能遍历合同声明的 ArtifactRef 字段，逐个验证原 root 为 `validation_run`、路径可解析且原始字节 hash/长度相等，再从同一 `replay/output` 目录生成 `replay_validation` 引用；禁止字符串替换、alias map 或修改 T03 原始文件。

未来取得用户代码授权后，仅允许修改：

```text
apps/chrome-extension/e2e/run-v2-px-r4-snapshot-revalidation.mjs
apps/chrome-extension/e2e/lib/v2PxSnapshotReplay.mjs

对应三个 *.node-test.mjs

docs/active/project/contracts/v2_px_snapshot_input_manifest.schema.json
```

实际只在产生或规范化 Replay InvocationRecord 的最窄位置统一 `artifactRoot`。若无需修改其中某文件，应在实现交接中标记 `not_changed`；不得为了凑齐列表触改。

## 3. 禁止修改

- 不修改 T02/T03、产品 UI、Runtime、Adapter、Permission、Forget、公共 API 或 T03 InvocationRecord Schema。
- 不修改或覆盖 `t04-r4-snapshot-revalidation-20260914t105407z`、其 ExitManifest、public archive 和独立审计。
- 不把 `validation_run` 注册为长期别名，不在 PX-6 reader 中容忍两种命名。
- 不只重建 JSON 或 Replay lane，不复用旧 R4-E、旧 raw、旧 profile、旧 Runtime/database 或旧 seal。
- 不运行旧 PX generator/validator，不扩大 normalization allowlist，不签署 Human Review。

## 4. 实施序列

```text
T04.1-0 读取本计划、验收计划、T04 原审计和用户授权摘要
T04.1-0a 验证 Snapshot Input Manifest 已冻结 T04.1 审计、授权、stage、scope 与 userId
T04.1-1 增加 artifactRoot 一致性失败回归
T04.1-2 生成并验证 resolved-invocation-record.json，保持原始 invocation 字节不变
T04.1-3 执行 T04 Node tests
T04.1-4 从新的空 output root 完整执行 T04-0..T04-7
T04.1-5 生成全新 R4-P、R4-E、raw/seal、SnapshotRevalidation、ExitManifest 和 public archive
T04.1-6 两轮内部审计
T04.1-7 重建外部实现审计包并取得独立审计 Fatal=0/Major=0
```

T04.1 外审必须写入 `t04.1-independent-implementation-exit-audit.md`，不得覆盖历史 `independent-implementation-exit-audit.md`。审计包仍为不超过 20 个平铺文件。

任何子阶段失败都使新 run 作废；只保留 diagnostic，不补 ExitManifest，不借用历史候选。

首次 run `t04-r4-resolved-invocation-20260914t142529z` 已按此规则作废：它在 T04-1 被旧 Input Manifest 授权常量拒绝，没有 replay、Chrome、seal 或 ExitManifest。兼容修复必须先完成独立文档审计，并以新的审计 hash 重建授权；禁止续跑该目录。

## 5. 目标体验与架构影响

本修复不改变用户界面。其价值是让 PX-6 对人工审查证据的解析只有一个 root 语义，避免错误读取 baseline 或其他 validation run。产品体验仍由 R4-E 全新真实 Chrome 复验证明。

## 6. 出门条件

- 新 T04.1 run 使用新的 runId、detached acceptance commit、build/profile/Runtime/database/raw/seal。
- Snapshot Input Manifest 必须 Schema-valid，并把外审、授权、`stage=T04.1`、批准 scope 与 `userId=repository_owner_current_chat` 绑定到实际原始字节。
- R4-P、R4-E、T04-A01..A14、T04-N-001..025 全部重新通过。
- 原始 Replay InvocationRecord 仍通过 T03 Schema，且其字节用于 10 exact + 1 normalized + 8 logs 比较；派生 Replay InvocationRecord 根和所有 step ArtifactRef 的 `artifactRoot` 精确为 `replay_validation`。
- 旧候选所有锚定字节保持不变。
- 新候选独立实现审计 `Fatal=0 / Major=0`；Minor 可记录但不得再包含 artifactRoot 命名歧义。
- Human Review/G7/final 仍为 `pending/pending/false`。
