## 7. 必答 7 问逐项复现

### Q1 — 双记录是否避免修改 T03 合同和旧候选，同时真正关闭 PX-6 root 歧义？

**答：静态 PASS。**

证据链：

1. T03 原始合同（开发计划 §1、Snapshot 合同 §1）：原始 `invocation-record.json` 必须保留 `validation_run`，继续用于 R4-P 确定性比较。Resolved Schema 不替代也不引用原 schema，是独立新增的 `v2-px-replay-invocation-record/v1` 合同（manifest item 9 SHA `9a191623…fc87f`）。
2. Resolved Schema `ReplayArtifactRef.artifactRoot = const "replay_validation"`（schema 行 39），且 sourceInvocation/steps[*]/productionPackage 全部走同一 `ReplayArtifactRef` 通道；负例 N1/N2/N3/N6 全部命中 const 拒绝（§3）。
3. 旧 T04 候选（`t04-r4-snapshot-revalidation-20260914t105407z` 及其 ExitManifest/public archive/独立审计）由 Snapshot 合同 §4 + 验收计划 §2 T04.1-A01 + 开发计划 §3 显式禁止覆盖与回写；本审查未发现任何对旧候选字节的修改指令。
4. SnapshotRevalidation Schema 强制 `replayLane.actualInvocation` 必须 root=`replay_validation` 且 path=`resolved-invocation-record.json`（§4.4）—— PX-6 reader 没有第二条入口可走。
5. 双记录语义在 Draw.io v2p-02 / v2p-06 / v2p-07 三处显式文字标记（§6.1）。

判定：root 命名歧义在 schema + drawio 双层都被关闭。

### Q2 — resolved Schema 是否强制所有 ArtifactRef 为 `replay_validation`，并拒绝 alias、混合 root 和路径逃逸？

**答：静态 PASS（Minor 见 §15 M-1）。**

证据：

- `ReplayArtifactRef.artifactRoot: const "replay_validation"`，没有 alias / enum / 兼容值（schema 行 38–39）。
- `additionalProperties: false` 防止塞入 `alias`、`compatibilityRoot`、`originalRoot` 等额外字段（schema 行 36–37）。
- 负例 N1–N3 + N6 证实 sourceInvocation / step implementation / step stdout / productionPackage 任一位置 `validation_run` / `baseline_validation` 都会被立即拒绝（§3）。
- 路径逃逸：`RelativePath` regex 阻断 `/abs`、`..`、NUL（§3.1）。`virtual/` 仅在首段阻断（Minor M-1，§15）。
- SnapshotRevalidation Schema 进一步把 `replayLane.actualInvocation` 锁定为 `replay_validation` + `resolved-invocation-record.json`（§4.4），即使有人塞 resolved schema 之外的 ArtifactRef 也无法接入 R4-P。

### Q3 — `sourceInvocation`、派生算法及原始 SHA-256 不变要求是否足以证明 resolved 记录来自真实原始字节？

**答：静态 PASS（存在一道校验依赖 validator 实现）。**

证据：

1. `sourceInvocation` 是 resolved schema 的 `required` 字段（schema 行 7），且强制 `artifactRoot=replay_validation` + `path=invocation-record.json`（schema 行 13）；运行时不能省略。

## 11. Minor 项（2 项，不阻断 CONDITIONAL GO）

### M-1 — Resolved Schema `RelativePath` 的 `(?!virtual/)` 仅阻断首段

**位置**：`09-resolved-invocation.schema.json` 行 34。

**现象**：`subdir/virtual/file.json` 通过 regex；`virtual/anything.json` 拒绝。

**风险**：低。Snapshot 合同 §1 明确 virtual/ 是顶层 prefix 标记（与 `virtual artifact 必须逐路径绑定一次解析的 UTF-8 或 canonical JSON 精确字节, 禁止二次反转义` 协同），文档语义上 resolved 记录不应嵌入虚拟 artifact；但 schema 当前没有强制这条约束。PX-6 Exit Schema 的 `RelativePath`（`14-px6-exit.schema.json` 行 63）甚至没有 `(?!virtual/)` 检查，与 resolved schema 不对称。

**建议（非阻断）**：在 `09-resolved-invocation.schema.json` `RelativePath` 中将 `(?!virtual/)` 改为 `(?!.*(?:^|/)virtual(?:/|$))`，并在 `14-px6-exit.schema.json` 同步；或在 contract 文档 §1 显式声明 virtual/ 限制为首段 prefix 并由 validator 显式 reject mid-path virtual。

### M-2 — 原始字节恒等与四子进程实跑依赖 validator 实现而非 schema

**位置**：`08-snapshot-contract.md` §1、§3.1、`06-t04.1-acceptance-plan.md` §2 不可变性段。

**现象**：schema 只规定 `stepResults[*].invoked: const true` / `exitCode: const 0` / 各 ArtifactRef 形状；"原始 invocation-record.json 派生前后 SHA-256 恒等"、"四步必须由子进程实跑并读取真实 stdout/stderr 字节"等要求写在 contract 文本与验收项中，不在 schema 强约束。

**风险**：低-中。Schema 通过 ≠ validator 通过；若未来 validator 实现偷懒只写 self-reported bool，仍可能产生 false-green。

**建议（非阻断）**：在 T04.1 实施阶段把"原始字节恒等"作为 `replayLane.stepResults[*]` 的 schema 约束（例如 prefixItems 中嵌入 `byteLengthMatch: const true` / `rawStderrSha256: $ref Sha256` 等），或在 `08-snapshot-contract.md` §3.1 增加对应 schema 字段，让 snapshot schema 自身能 fail closed。
