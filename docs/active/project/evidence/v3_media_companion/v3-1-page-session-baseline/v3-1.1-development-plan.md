# V3-1.1 媒体页面采集开发计划

日期：2026-09-17  
状态：`IMPLEMENTATION CANDIDATE`  
父阶段：V3-1 B站页面、会话与能力基线。

## 1. 目标体验

1. 用户打开受支持的 B站视频详情页时，Navia 自动识别视频、分 P、当前播放单元、标题、作者、时长、播放位置和字幕可用性。
2. 通用 UI 与后续 Runtime 只接收 `MediaPageContext`，不接触 bvid/cid 等平台专有字段。
3. 普通网页不再安装后自动出现常驻 launcher；用户点击扩展 action 或快捷键后，才以 `activeTab` 注册 bridge 并打开原生 Side Panel。
4. YouTube、小红书本阶段保持未实现；未来新增门户只增加独立 adapter/registry descriptor，不修改通用 context、消息类型或调用方。

## 2. 实施实体

新增前端模块：

```text
apps/chrome-extension/src/modules/media_companion/
  contracts.ts
  MediaPortalAdapter.ts
  MediaPortalRegistry.ts
  index.ts
  adapters/bilibili/bilibiliUrl.ts
  adapters/bilibili/bilibiliPageState.ts
  adapters/bilibili/BilibiliMediaPortalAdapter.ts
  tests/MediaPortalRegistry.test.ts
  tests/BilibiliMediaPortalAdapter.test.ts
```

职责：

- `contracts.ts`：通用 `MediaPageContext`、part、transcript 状态、采集失败码和消息响应；字段对齐 Schema v3。
- `MediaPortalAdapter.ts`：冻结 `match/collect/readPlayback/seek/capabilities` 接口；不含任何 B站字段。
- `MediaPortalRegistry.ts`：构建期封闭 registry、唯一匹配、重复匹配 fail closed；只注册 B站 revision 1。
- `bilibiliUrl.ts`：BVID、`p`、canonical URL 规范化；拒绝非 HTTPS、非 video path 和非法 BVID。
- `bilibiliPageState.ts`：只读取当前真实 DOM、bootstrap JSON 和真实 `<video>` 状态；不调用 Cookie API，不把标题/简介当字幕。
- `BilibiliMediaPortalAdapter.ts`：把 bvid/cid/pages 映射到通用 mediaId/playbackUnitId/part；页面身份不完整时 fail closed。

修改入口：

```text
apps/chrome-extension/src/contentBridge.ts
apps/chrome-extension/src/contentBridge.test.ts
apps/chrome-extension/entrypoints/content/index.ts
apps/chrome-extension/entrypoints/background/index.ts
apps/chrome-extension/wxt.config.ts
apps/chrome-extension/package.json
```

- 新增 `navia.media.collectPageContext`、`navia.media.readPlayback`、`navia.media.seek` 消息。
- `initializeContentBridge` 增加 `portal_auto` / `bridge_only` 模式；B站静态脚本使用前者，普通网页 action 注入使用后者。
- content script 静态 match 只保留 `https://www.bilibili.com/video/*`；WAR 按 Chrome MV3 合法 pattern 固定为 origin 级 `https://www.bilibili.com/*`，不得据此扩展自动注入路径。
- background 删除 tab update/activate 的隐式全站注入；仅 action/command 调用 `chrome.scripting.executeScript` 后打开原生 Side Panel。
- manifest 删除 `<all_urls>` 和等价 host；保留 loopback Runtime host。Cookie 与 B站 wildcard host 仍属于 V3-1.2，不在本子阶段加入。

新增验收工具：

```text
apps/chrome-extension/e2e/v3-media-page-collector.mjs
apps/chrome-extension/e2e/v3-route-a-static-audit.mjs
```

- collector 使用全新 build/profile 和真实 Chrome，逐页通过扩展 service worker 向真实 content script 发送采集消息。
- static audit 对源码、构建 manifest、content-script matches、WAR、portal registry 与 import graph 做机器对账。

## 3. 顺序

1. 实现通用合同、adapter interface、构建期 registry 与纯函数单测。
2. 实现 B站 URL/bootstrap/播放器采集和单测。
3. 接入 content bridge 的三个媒体消息并回归旧 page context/jumpback。
4. 落实路线 A manifest/background/content entrypoint，构建后运行静态权限审计。
5. 运行全量前端测试、typecheck、build。
6. 使用冻结 12 页注册表执行一个全新 real-Chrome run，产出 12 个 context、截图、build/registry hash 和结果索引。
7. 落盘 acceptance result、PRD review、false-green audit 与 handoff。

## 4. 非目标

- 不读取 `chrome.cookies`，不请求可选 B站 host，不创建 credential lease。
- 不下载字幕、音频或视频；不执行 ASR/OCR/VLM。
- 不增加 Side Panel 媒体授权 UI，不生成 outline、timeline、mindmap 或 Ask。
- 不实现 YouTube/小红书 adapter，不增加远程 adapter 或动态代码加载。
- 不修改 V2/PX/RKM 已封存证据。

## 5. 停止条件

- 真实页面无法从当前 DOM/bootstrap 得到稳定 identity，且需要 Cookie/API 权限才能继续。
- 任一构建产物仍含全站匹配或普通页自动静态注入。
- 通用合同出现 bvid/cid 等平台字段，或一个 URL 匹配多个 adapter。
- 12 页真实 run 出现 2 个及以上身份漂移、跨 run 拼接需求、fixture 代替真实结果或秘密值进入 evidence。
- 旧 page context/jumpback 主流程发生 Major 回归。
