# V3-1.1 Chrome WAR pattern 风险闭环

日期：2026-09-17  
状态：`CLOSED BEFORE ACCEPTANCE RERUN`

## 1. 发现

首次真实 Chrome run 在加载扩展前失败。Chrome 扩展日志给出：

```text
Invalid value for 'web_accessible_resources[0]'. Invalid match pattern.
```

原文档与实现把 `web_accessible_resources.matches` 冻结为 `https://www.bilibili.com/video/*`。Chrome MV3 的 WAR match pattern 只接受 origin 级路径 `/*`，因此该配置会导致整个扩展拒绝加载。此前 Schema、静态 audit 和独立文档审查只检查了“窄域”，没有验证 Chrome 对 manifest 的实际加载。

## 2. 最小修复

- content script 静态匹配保持 `https://www.bilibili.com/video/*`；
- WAR 匹配改为 `https://www.bilibili.com/*`；
- 普通路径和其他站点仍不得自动注入；
- `host_permissions` 仍只有两个 loopback Runtime origin；
- Cookie 与 `https://*.bilibili.com/*` 仍推迟到 V3-1.2；
- 同步更新 portal registry、positive fixture 原始字节 hash、架构、ADR、开发计划、验收计划和静态 audit。

## 3. 风险判断

这不是 PRD 功能扩张。WAR 只决定网页可请求哪些列出的扩展资源，不产生 content-script 注入；自动入口仍由 `/video/*` 的静态 content script 单独控制。YouTube、小红书和普通页面均未新增静态匹配或 host permission。

## 4. 重新出门条件

1. Chrome 实际加载 build manifest，不再出现 manifest load error；
2. 构建 manifest 的 content script 精确为 `https://www.bilibili.com/video/*`；
3. WAR 精确为 `https://www.bilibili.com/*`；
4. 普通页和 B站非视频页均无静态 bridge/launcher；
5. portal registry 原始字节 SHA-256 与 positive fixture 重新对账；
6. 12 页真实 Chrome 分母从全新 run 重新执行，失败诊断 run 不进入通过分母；
7. V3-1.1 实施出门包必须披露本闭环，并由独立审查者复核。
