## 3. 证据结构

每个 segment 记录：`runId/buildSha256/portalRegistrySha256/sessionRegistrySha256/schemaSha256/profileSegment/evidenceClass/adapterId/policyId/policyRevision/permissionState/capabilityStatus/serverValidated/credentialCount/nameSetSha256/observedAt/expiresAt/failureCode`。

不得记录：Chrome profile 路径、账号、昵称、UID、Cookie 名列表、Cookie 值、完整 header、可逆值 hash、B站登录页全屏截图。

截图只裁切扩展 UI，且需包含：未授权、拒绝、匿名授权后不可用、登录授权后候选可用、撤销后、键盘焦点。

## 4. 防假绿

以下任一项为 Major 或 Fatal：

- 用 fixture Cookie、产品 `chrome.cookies.set`、复制 profile 或预制产物冒充真实登录正例。唯一例外是补充条款约束的验收 harness CDP 一次性种子；它必须标为 `user_authorized_live_session_seed`、通过服务端有效性验证并销毁 profile。
- 只看 UI badge，不复核 `chrome.permissions.contains` 和 Cookie API 读取计数。
- 将 `available/serverValidated=false` 宣称为 B站服务端登录已验证。
- 从消息中接受 origin/Cookie names，或在通用层硬编码 B站字段。
- Background 代替可见点击调用 `permissions.request`，或在启动/页面打开时自动请求。
- 撤销后仍能读 Cookie，或缓存旧 `available`。
- 任一 Cookie 值进入持久介质、日志、错误、截图、公开证据或审计包。
- 为了通过验收而扩大 host 到 `https://*/*`、降低密密扫描或省略真实登录 segment。
- 把 V3-1.2 扩大为凭据租约、下载、视频理解或未来门户适配完成。
