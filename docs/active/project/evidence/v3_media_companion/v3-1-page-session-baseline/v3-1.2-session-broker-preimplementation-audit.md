## 3. 三项 Minor

1. **M-1 真实登录依赖人类**：自动化不得登录或复制主 profile。这是刻意的高风险停点，不能用 mock 规避。
2. **M-2 Cookie 名称可随平台变化**：当前政策继承 PRD/架构冻结的 9 名；真实 profile 不满足时必须 fail closed 并回到文档修订，禁止实现内放宽。
3. **M-3 V3-1.3 仍有独立高风险面**：本设计不证明 Browser→Runtime 秘密传输安全；必须另做 envelope/lease/replay/redaction 威胁建模。

## 4. 审计意见闭环

- V3-1.1 外部报告的 Fatal/Major/Minor 均为 0，状态已回写 Stage Gate/README。
- 权限请求的用户手势边界已从含糊的“Background Broker 请求”修订为 `PortalPermissionClient` 在扩展页面直接请求，Background 只复核。
- 开放性已从只有 `MediaPortalAdapter` 补强为独立 `PortalSessionAdapter/Registry/Broker`，B站 Cookie 政策不进入通用层。
- V3-1.2 与 V3-1.3 分期已冻结：本阶段不传值、不签租约、不下载。

## 5. 门禁与待审结论

独立文档审计必须回答：

1. 通用 session 合同是否真正不依赖 B站字段。
2. Chrome 用户手势与 optional permission 位置是否可实现。
3. 从 Cookie Store 到 capability 的每一步是否可防止值序列化。
4. 撤销、TOCTOU、缓存和 service worker 重启是否 fail closed。
5. 登录正例、匿名负例和秘密扫描是否能拒绝假绿。
6. YouTube/小红书是否可通过独立适配方式接入，又不会继承 B站权限或 PASS。

在外审 Fatal=0/Major=0 且用户单独确认 Cookie 高风险实施前，`V3-1.2 implementation` 保持 NO-GO。
