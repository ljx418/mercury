# V3-1.2 Cookie 权限与门户会话能力威胁模型

日期：2026-09-17。版本：1。数据等级：`credential secret / account session`。

## 1. 信任边界

| 边界 | 从 | 到 | 控制 |
|---|---|---|---|
| B1 | 人类 | Side Panel 授权按钮 | 可见五 scope；真实 click；可拒绝/撤销 |
| B2 | Side Panel | Chrome Permissions API | 权限只来自 build-time registry；直接在 click handler 调用 |
| B3 | UI/message | Background Broker | 严格 command schema；只传 adapterId；不接受 host/名称/值 |
| B4 | Broker | Chrome Cookie Store | policy + revision + permissions.contains 四重复核；只读 |
| B5 | Cookie Store | B站 session adapter | 白名单；单次调用内存；只派生 count/name-set hash/status |
| B6 | Broker | UI/evidence | 只冻结 `PortalSessionCapability`；`serverValidated=false`；不输出值 |

V3-1.2 不存在 Browser→Runtime 秘密边界；该边界必须在 V3-1.3 重新威胁建模。

## 2. STRIDE 风险

| ID | 威胁 | 严重度 | 可利用场景 | 缓解/验收 |
|---|---|---|---|---|
| T01 | 伪造授权消息 | High | 页面/content script 直接发 `record_grant` | Background 复核 `permissions.contains`；不信任 caller 自报 |
| T02 | 诱导扩大 host | Critical | message 携带任意 origin 请求 Cookie | router 拒绝额外字段；只从注册表取权限；0 全站 wildcard |
| T03 | Cookie 值外泄 | Critical | result/log/error/storage/E2E 序列化 Chrome Cookie | 值只在 adapter 栈内；全介质 needle 扫描 0 命中 |
| T04 | 旧能力重放 | High | 撤销或 logout 后缓存 `available` | TTL 30s；撤销立即清缓存；每次复核 permission/policy revision |
| T05 | 白名单漂移 | High | 开发者静默新增 Cookie 名 | registry 和源码集合比较；增名必须回到文档/安全审计 |
| T06 | 账号身份泄漏 | High | 截图/证据包含昵称、UID、profile 路径 | 截图只裁 UI；evidence schema 禁止；公开包扫描 |
| T07 | 权限请求无用户手势 | High | 启动时/background message 自动请求 | 只 `PortalPermissionClient` 调用；静态扫描；真实 Chrome 点击时序 |
| T08 | 假登录结论 | Medium | 仅存在 SESSDATA 即宣称服务端有效 | 合同 const `serverValidated=false`；UI 文案“已检测会话候选” |
| T09 | 新门户继承 B站秘密 | High | YouTube/XHS adapter 复用 B站 host/白名单/PASS | 注册表分离；未注册 fail closed；独立权限与真实矩阵 |
| T10 | 扩展页面 XSS 窃取结果 | High | UI 注入未信任平台文本 | 能力合同无秘密；React 默认 escape；不使用 `dangerouslySetInnerHTML` |
| T11 | TOCTOU | High | contains 通过后用户立即撤销，仍读 Cookie | 在单次 broker 调用中紧邻 contains/read；撤销序列化；撤销终态再复核 contains=false |
| T12 | 取证脚本反而泄密 | Critical | secret scanner 把 needle/hash 写入报告 | scanner 只在进程内比对；输出 0/命中数和名称集合 hash；报告自身再扫描 |

## 3. 负面用例最小集

1. 未授权 inspect，预期 0 Cookie API call。
2. `record_grant` 伪造为 true 但 Chrome permission=false，预期拒绝。
3. 未注册 adapterId，预期 `V3_MEDIA_SESSION_ADAPTER_UNSUPPORTED`。
4. 传入 `origins/cookieNames/cookieValue`，预期 schema/router 拒绝。
5. Cookie Store 含非白名单名称，预期输出计数/hash 不包含它。
6. `SESSDATA` 缺失或空，预期 unavailable。
7. Chrome API 抛错，错误内含假 secret，预期对外错误被清洗。
8. 撤销后重放旧 capability，预期 revoked。
9. policy revision 与 registry 不匹配，预期 `V3_MEDIA_SESSION_POLICY_MISMATCH`。
10. 普通页或未注册门户打开 Side Panel，预期无门户授权请求。

## 4. 残余风险

- Chrome/B站可变更 Cookie 结构；本阶段选择 fail closed，不自动扩大白名单。
- `SESSDATA` 存在不代表服务端有效；V3-1.3 必须使用一次性 envelope 进行受控验证。
- 人类登录 profile 仍是敏感环境；验收完成后必须删除专用 profile，且公开包不含 profile。
- 本阶段不能证明任何媒体获取能力，也不能证明 YouTube/小红书会话适配可行。

这些残余风险不可靠降低验收门槛消除；只能在后续阶段通过真实服务端调用、独立 adapter 文档和专属矩阵逐项关闭。
