# V3-1.2 用户授权实时会话引导补充条款

日期：2026-09-17。状态：`FROZEN ADDENDUM`。本条款只补充验收输入，不改变产品架构、产品权限或运行时合同。

## 1. 目的

原 V3-1.2-A07 只允许人类在专用 profile 手动登录。用户现已明确授权一次性读取桌面 `myCk.txt`。为了避免把该授权误实现为产品文件读取、fixture 注入或伪造登录证据，新增第二种独立证据类别：

```text
user_authorized_live_session_seed
```

两种正例互不冒充：

| 证据类别 | 来源 | 可声明范围 |
|---|---|---|
| `human_manual_login` | 人类在专用验收 profile 可见登录 | 人工登录产品路径与候选会话能力 |
| `user_authorized_live_session_seed` | 用户明确授权的实时 Cookie 文件，一次性写入全新验收 profile | 产品从 Chrome Cookie Store 派生候选能力；不证明人工登录路径 |

## 2. 一次性引导约束

1. 只允许读取用户指定的绝对路径 `/mnt/c/Users/Administrator/Desktop/myCk.txt`。
2. 读取进程不得打印、记录、复制、缓存或散列 Cookie 值；原始文件 SHA-256 也不得进入证据。
3. 解析器只接受 JSON Cookie 数组；所有记录的 domain 必须是 `bilibili.com` 或其子域。
4. 只把注册表冻结的 9 个名称写入一次性 profile；未知名称默认拒绝。`SESSDATA` 必须存在且非空。
5. 写入只能由验收 harness 通过 Chrome DevTools Protocol 对一次性 profile 执行；产品扩展不得调用 `chrome.cookies.set`，不得读取文件。
6. profile 必须使用本 run 独立目录；不得复制、复用或挂载用户主 profile。
7. 写入后必须访问冻结的 B站锚点并执行真实同源服务端会话探测；只有服务端返回当前会话有效且页面/接口身份一致时才可进入 A07 capability 观测。
8. 对持久产物执行进程内 needle 扫描时只输出 `hitCount`、冻结名称集合 hash 和扫描文件数；任一命中立即作废 run。
9. run 完成或失败后关闭 Chrome，删除一次性 profile，并验证无遗留进程、无遗留 Cookie 数据目录。
10. 审计材料必须记录 `evidenceClass=user_authorized_live_session_seed`，不得写成 `human_manual_login`。

## 3. 不变的产品边界

- `PortalPermissionClient` 仍只能在可见扩展页面的真实用户点击中请求权限。
- `BilibiliPortalSessionAdapter` 仍只读 Chrome Cookie Store，且只返回不含秘密的 `PortalSessionCapability`。
- `serverValidated` 在 V3-1.2 合同中仍固定为 `false`；验收 harness 的服务端有效性检查只证明测试输入不是 fixture，不升级产品 capability 语义。
- V3-1.2 仍不实现 Browser 到 Runtime 秘密传输、租约、下载或视频理解。

## 4. 防假绿

以下任一项为 Major：产品代码读取 `myCk.txt`；把种子计为人工登录；跳过服务端有效性探测；输出任一 Cookie 值或其可逆 hash；保留一次性 profile；接受非 B站域；写入注册表外名称；用旧 run/旧 profile 拼接正例。
