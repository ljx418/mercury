# V3-1.3-1 Runtime 精确 Origin 与一次性 Channel 验收卡

日期：2026-09-17。状态：`READY FOR IMPLEMENTATION`。

## 1. 实施前风险检查

先用真实 Chrome 对 unpacked extension 的产品页面和 Background service worker 发往 loopback 的请求做 Origin 探针。必须记录 extension ID、调用上下文、是否发生 OPTIONS、实际 Origin；不得记录 Cookie、Runtime bearer 或 profile 路径。若 Origin 缺失或不能稳定绑定精确 extension ID，立即停止，不得放宽为任意 `chrome-extension://`。

## 2. 实施范围

- Runtime `MediaCredentialAuthenticator`：强 bearer、精确 `chrome-extension://<configured-id>` Origin。
- `CredentialChannelStore`：256-bit CSPRNG ticket、20 秒 TTL、进程内、单次消费。
- `POST /v1/media/credential-channels`：严格公开 metadata、no-store、只返回 transient token + public record。
- Runtime 层先拒绝通用认证/错误 Origin；本阶段不读取 Cookie、不接收 envelope、不创建 lease。

## 3. 验收标准

| ID | 操作 | 必须结果 |
|---|---|---|
| `V3-1.3-1-A01` | 真实 Chrome Origin 探针 | 产品 extension 页面和 Background 的 loopback Origin 行为被实测并支持精确绑定 |
| `V3-1.3-1-A02` | Runtime token 缺失/错误/弱配置 | exact `V3_MEDIA_RUNTIME_AUTH_REQUIRED`；0 channel |
| `V3-1.3-1-A03` | Origin 缺失/任意 extension/http localhost | exact `V3_MEDIA_RUNTIME_ORIGIN_MISMATCH`；0 channel |
| `V3-1.3-1-A04` | 正确 token + exact Origin + strict body | 256-bit ticket；20 秒；公开 record 无 token；`Cache-Control: no-store` |
| `V3-1.3-1-A05` | 首次 consume、第二次 consume、过期 consume | 首次成功；重放 exact replayed；过期 exact expired；store 不复活 |
| `V3-1.3-1-A06` | Runtime 单元/HTTP/旧回归 | 新测试与 Runtime 既有测试全 PASS；无 body/secret log |

## 4. PRD 与出门

该阶段只创建一次性 transport capability，不显示“会话租约已就绪”。全部验收通过并落盘结果/PRD review 后，才进入 UI channel client 与 trusted message schema。
