# V3-1.3-2 UI Channel Client 与受信消息验收卡

日期：2026-09-17。状态：`READY FOR IMPLEMENTATION`。

## 1. 实施范围

- `PortalCredentialChannelClient` 在现有 `runtimeClient` 内存认证边界内直接 bootstrap channel；不得返回或暴露 Runtime bearer。
- `PortalCredentialMessageClient` 只发送冻结字段：channel token、channel 公共记录和严格 task/adapter/policy/binding metadata。
- `PortalCredentialMessageRouter` 仅接受自身 extension ID 且 URL 为 `sidepanel.html` 或 `workspace.html`，拒绝有 tab 的 content script、外部 extension、options/其他 extension 页和额外字段。
- Background 在本阶段只验证 sender/message 并调用可注入 handler；不得读取 Cookie或调用 lease endpoint。

## 2. 验收标准

| ID | 操作 | 必须结果 |
|---|---|---|
| `V3-1.3-2-A01` | UI 使用当前内存 token bootstrap | 正确 Authorization 与 exact Origin；返回 transient channel；主 bearer不出模块 |
| `V3-1.3-2-A02` | token 未配置/Runtime 错误 | fail closed；不发送 Background 消息 |
| `V3-1.3-2-A03` | 正常 sidepanel/workspace sender | 严格消息通过并仅调用一次 handler |
| `V3-1.3-2-A04` | content script/外部 ID/options/任意页/额外字段 | exact reject；handler 0 调用；Cookie read 0 |
| `V3-1.3-2-A05` | storage/序列化静态检查 | 主 bearer与 channel token 不写 storage、URL、日志、React state/E2E observation |
| `V3-1.3-2-A06` | 前端测试/typecheck/build | 新测试、现有 session tests、typecheck 与 build PASS |

## 3. PRD 门禁

本阶段只建立 UI→Background 的受信命令通道，不应新增“分析完成”体验。完成验收与 PRD review 后才允许实现 Background B站 envelope broker。
