# V3-1.3-2 UI Channel Client 与受信消息验收结果

日期：2026-09-17。结论：`PASS`。Fatal=0、Major=0。

## 1. 实施结果

- `runtimeClient.bootstrapMediaCredentialChannel` 在内存 session 闭包内直接请求专用 endpoint；不经过通用 proxy 或 R2 body observation。
- `PortalCredentialChannelClient` 先取得 Background 公开 binding，再创建 channel 并只转交一次 transient token。
- `PortalCredentialMessageRouter` 严格限制自身 extension ID、`sidepanel.html/workspace.html`、无 tab sender 和字段闭集。
- Background service worker 启动时生成 32-byte 随机实例，仅暴露 domain-separated SHA-256 binding；原始实例在摘要完成后清零。

## 2. 验收

| 验收项 | 实际结果 |
|---|---|
| A01 专用 bootstrap | Authorization 只在闭包内；no-store/omit/error/no-referrer；响应严格校验 |
| A02 缺 token/错误 | 缺 token fail closed；Background 消息不发送 |
| A03 受信 sender | sidepanel/workspace 各通过并精确调用一次 handler |
| A04 非受信 sender | content script、外部 ID、options、缺 URL、额外字段、binding mismatch 全拒绝；handler 0 调用 |
| A05 非持久化 | binding 只含摘要；bearer 不在 snapshot；未新增 storage/URL/log/React state 写入 |
| A06 回归 | 定向 56 tests PASS；前端全量 35 files / 267 tests PASS；typecheck PASS；E2E build PASS |

## 3. 边界

Background exchange handler 当前仍 fail closed，不读取 Cookie、不发送 Runtime envelope、不签发 lease。该能力在 V3-1.3-3/4 实现。
