# V3-1.3-7 PRD 规格检视

日期：2026-09-17。对象：`v3-1.3-credential-20260917T134817Z-final3`。

## 1. 已达成的本阶段体验

- 用户在真实 B站视频页首次同意五项用途与 Chrome 可选权限后，可在 Side Panel 或 `#/media/current` Workspace 连接本机 Runtime 并点击“重新建立会话”。
- UI 只显示会话候选、建立中、短租约已就绪或失败；不显示 Cookie 名/值、channel token、revocation token、账号身份或 profile 信息。
- ready 文案明确“媒体获取将在 V3-2 提供”，没有宣称登录有效、媒体已下载或视频已理解。
- 撤销会移除 Chrome 权限、阻止旧 authority，并清理 Background revocation handle；Runtime/Background 重启均 fail closed。

## 2. 架构一致性

数据流保持单向：

```text
Side Panel / Workspace
-> 专用 PortalCredentialChannelClient
-> Runtime exact-Origin channel bootstrap
-> Background trusted message router
-> BilibiliCredentialEnvelopeBroker 一次读取冻结 Cookie 集
-> 专用 loopback envelope POST
-> Runtime process-memory-only PortalCredentialLease
```

通用 Runtime fetch/stream 不能访问 credential endpoint；content script、普通 extension tab 和错误 Origin 在 Cookie read 前拒绝。通用 channel/lease 层对 `bilibili.com/SESSDATA/bvid/cid` 扫描为 0，门户字段仍封装在 B站 plugin/registry，未注册 YouTube/小红书。

## 3. PRD 未越界

- 未下载字幕、音频或视频。
- 未实现 ASR、关键帧、OCR、VLM、大纲、时间线、Mindmap、Ask、jumpback 或导出。
- 未恢复 V2 Query/Graph/Durable Forget，也未声明 V4 记忆/外脑完成。
- B站服务端登录真实性只由同 build 的 V3-1R 测试输入检查；产品公开 lease 仍固定 `serverValidationStatus=not_performed`。

## 4. 结论

V3-1.3 的“Browser-to-Runtime 一次性凭据传输与短期内存租约”目标已形成可独立复核的本地出门候选。其完成不会自动放行 V3-2；下一步仅允许独立实施审查，审查 Fatal=0/Major=0 后再制定 V3-2 详细计划与高风险边界。
