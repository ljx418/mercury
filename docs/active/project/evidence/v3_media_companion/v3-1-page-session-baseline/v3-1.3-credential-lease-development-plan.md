# V3-1.3 Browser→Runtime 一次性凭据通道与短租约开发计划

日期：2026-09-17。状态：`DOCUMENT CANDIDATE / IMPLEMENTATION NO-GO`。

## 1. 目标与边界

V3-1.3 只完成一个高风险边界：在用户已授予 V3-1.2 五项产品 scope、Chrome 可选权限仍存在且 Runtime 已认证时，把 Background 从当前 Cookie Store 读取的 B站白名单凭据经一次性 loopback envelope 交给 Runtime 内存，并返回不含秘密的同任务短租约。

本阶段不下载字幕、音频或视频，不创建 cookiefile，不调用 ASR/OCR/VLM，不宣称 B站服务端会话有效，也不实现 YouTube/小红书。媒体获取从 V3-2 开始。

用户可见的阶段结果仅为：点击“开始分析”后完成“正在建立本机安全会话 → 会话租约已就绪”，随后明确显示“媒体获取将在 V3-2 提供”，不得显示分析完成、字幕已获取或视频已理解。

## 2. 既有事实与必须修复的安全缺口

- V3-1.2 已实现 `PortalPermissionClient -> PortalSessionBroker -> BilibiliPortalSessionAdapter`，只输出 `serverValidated=false` 的候选能力；其 registry、Schema、run 和证据保持只读。
- Runtime 当前通用 CORS 接受任意 `chrome-extension://` Origin，不能作为秘密接口的授权依据。
- 现有 Runtime bearer 只保护部分 `/v1/knowledge/*` 路径；Background 没有可安全复用的持久 token。
- 通用 `runtimeClient` 和 Background `navia.runtimeFetch` 会产生请求观测，不能承载 Cookie request body。

因此 V3-1.3 使用两步、最小权限协议：现有 Runtime bearer 只创建短期 channel ticket；Background 再用 ticket 发送一次性 envelope。不得把主 bearer 或 Cookie 值写入 storage、消息日志、E2E observation、EventStore 或 Trace。

| 实体 | 目标位置 | 职责 | 禁止 |
|---|---|---|---|
| `PortalCredentialChannelClient` | `apps/chrome-extension/src/modules/media_companion/session/credential/` | Side Panel/Workspace 使用当前内存 bearer 创建 20 秒单任务 channel | 持久 token；读取 Cookie；复用通用 proxy |

| `MediaCredentialAuthenticator` | `services/local-runtime/navia_runtime/modules/media_companion/` | 校验主 bearer、精确 extension Origin、channel ticket | 仅凭 CORS/Origin 前缀放行 |
| `CredentialChannelStore` | 同上 | 256-bit ticket、20 秒 TTL、第一次请求即消费 | SQLite/文件/EventStore；复活已消费 ticket |
| `CredentialLeaseStore` | 同上 | 凭据只在 Runtime 进程内，租约最长 60 秒 | DB/配置/Trace；公开可用的秘密 handle |

未来门户只能新增独立 envelope broker、session policy 和真实矩阵；通用 channel/lease 协议不得包含 `bvid/cid/SESSDATA/bilibili.com`。

## 5. 冻结协议

### 5.1 Channel bootstrap

```text
Side Panel/Workspace trusted click
-> POST /v1/media/credential-channels
   Authorization: Bearer <existing in-memory Runtime token>
   Origin: exact chrome-extension://<NAVIA_LOCAL_FILES_EXTENSION_ID>
   body: taskId/adapterId/policyId/policyRevision/browserSessionBindingSha256/nameSetSha256
-> Runtime returns transient channelToken + public PortalCredentialChannelRecord(status=issued)
-> UI immediately sends token and exact metadata to trusted Background router
```

`channelToken` 是 256-bit CSPRNG 值，20 秒过期，只能使用一次，不得进入 React state dump、storage、URL、日志、公开 response 或证据。公开记录只保存 `channelId`。

### 5.2 Envelope exchange

```text
Background router
-> verify sender id + sidepanel/workspace URL
-> re-read V3-1.2 policy, permissions.contains and current capability
-> chrome.cookies.getAll registered Bilibili domain
-> filter exact frozen 9-name allowlist; require non-empty SESSDATA
-> POST /v1/media/credential-leases via dedicated fetch
   Authorization: Navia-Media-Channel <channelToken>
   redirect=error / cache=no-store / no same-body retry / max 32768 bytes
-> Runtime consumes channel before JSON decode
-> strict BilibiliCredentialEnvelope validation
-> Runtime process-memory lease + transient revocation token
-> Background keeps revocation token in service-worker memory
-> UI receives only PortalCredentialLease
```

进程内 `BilibiliCredentialEnvelope/v1` 固定字段：`envelopeId/channelId/taskId/adapterId/sessionAdapterId/policyId/policyRevision/browserSessionBindingSha256/credentialNameSetSha256/issuedAt/expiresAt/credentials[]`。每个 credential 仅含 Chrome Cookie API 返回的 `name/value/domain/path/secure/httpOnly/sameSite/expirationDate`；字段集合严格关闭。channel token 在 Authorization header，不在 body。

### 5.3 生命周期

- Channel TTL 最大 20 秒；第一次 exchange 无论 body 成功或失败都终结，避免解析 oracle 和重放。
- Lease TTL 最大 60 秒；仅 Runtime 内部持有 credential material。公开 `leaseId` 不是访问凭据。
- transport failure 状态不确定时禁止重发原 envelope；必须丢弃引用、重新创建 channel、重新读取 Cookie 并使用新 envelopeId。
- Runtime 重启清空 channel、replay cache 和 lease；旧 lease 查询返回 `V3_MEDIA_LEASE_EXPIRED`。
- permission/Cookie 变化、用户撤销或页面任务取消时，Background 用内存 revocation token 请求删除 lease；Background 崩溃/重启的残余窗口由 60 秒 TTL 上界限制。
- Browser service worker 启动时生成随机 session instance，仅公开其 domain-separated SHA-256 binding；不得 hash profile 路径、Cookie 值或账号标识。

## 7. 停止条件

- 需要把 Runtime 主 bearer 或 Cookie 值放入 `chrome.storage`、React state 持久层、URL、公开 JSON、日志、EventStore、Trace、异常或 retry queue。
- 需要放宽任意 `chrome-extension://` Origin、允许 content script/generic runtime proxy 调秘密 endpoint，或允许任意 adapter/host/Cookie 名。
- 无法证明第一次请求消费 ticket、同 envelope 不重试、Runtime restart 清空 lease。
- 使用 fixture Cookie、旧 run 或跨 run 拼接冒充真实生产正例。
- 把租约签发扩大为服务端会话验证、媒体获取、视频理解或未来门户已实现。
