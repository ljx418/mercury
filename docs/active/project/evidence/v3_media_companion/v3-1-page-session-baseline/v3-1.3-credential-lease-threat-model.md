# V3-1.3 Browser→Runtime 凭据通道威胁模型

日期：2026-09-17。版本：1。数据等级：`credential secret / account session / high risk`。

## 1. 资产与信任边界

| 边界 | 从 → 到 | 资产 | 强制控制 |
|---|---|---|---|
| B1 | 人类 → Side Panel/Workspace | 开始意图、Runtime bearer 输入 | 真实 click；password input；页面内存；不持久化 |
| B2 | Extension UI → Runtime channel endpoint | 主 bearer、task/policy binding | exact Origin + constant-time bearer；20 秒 channel；no-store |
| B3 | Extension UI → Background router | channel ticket、公开 binding | exact sender id/URL；字段闭集；content script 拒绝 |
| B4 | Background → Chrome Cookie Store | B站 session Cookie | 重查 policy/permission；registry 域与9名；单次 read |
| B5 | Background → Runtime lease endpoint | secret envelope | 专用 fetch；32768 bytes；一次请求；无 body 日志/观测/重试 |
| B6 | Runtime endpoint → lease store | credential material | 首次请求消费 ticket；严格 envelope；进程内；60 秒 TTL |
| B7 | Runtime → Background/UI/evidence | lease metadata、revocation capability | revocation token仅Background内存；UI/证据只见公开 lease |
| B8 | Permission/Cookie/Runtime lifecycle → lease | 撤销、重启、到期 | 主动 revoke + Runtime restart clear + 60 秒残余上界 |

## 3. 安全状态机

```text
channel: absent -> issued -> consumed | expired | revoked | failed
lease:   absent -> active -> consumed | expired | revoked | failed
```

禁止 `consumed -> issued`、`expired/revoked/failed -> active`。公开 leaseId 不是 capability；Runtime 内部按 task 和不可公开 handle 查找。channel 任何首次 exchange 都终结，格式错误也不得保留为 issued。

## 4. 负面攻击矩阵

至少覆盖：弱/错 bearer、任意扩展 Origin、无 Origin、content script、options page、generic proxy、额外字段、非注册 adapter、policy/revision/scope/permission 失配、缺 `SESSDATA`、body >32KiB、过期 ticket、ticket replay、envelope replay、task/binding/hash 篡改、响应丢失、Runtime restart、Background restart、permission remove、Cookie change、用户撤销、错误字符串注入 fake secret。

每个攻击用例必须证明“在读取 Cookie 前拒绝”或“Runtime active lease 数未增加”；仅检查 HTTP status 不足。

## 5. 残余风险与取舍

- Python/JavaScript 垃圾回收环境无法保证内存物理清零。本阶段通过最短引用生命周期、60 秒 TTL、进程重启清空和不复制到持久层降低风险，不宣称 secure memory。
- Background 崩溃后无法主动发送 revoke；残余窗口严格上限 60 秒。若 V3-2 证明 60 秒不足，不得直接放宽，必须设计可续期且同任务的内部消费协议并重新审计。
- loopback 使用 HTTP 而非 TLS；安全性依赖本机边界、强 bearer、精确 Origin和一次性 ticket。若 Runtime 未来监听非 loopback，协议立即失效并必须改为受认证加密通道。
- 扩展页面 XSS 会危及 channel ticket。保持 MV3 CSP、React escape、0 remote code，并在实施审计中做依赖/SAST检查。
- 服务端会话有效性与平台风控属于 V3-2 acquirer，不得借租约签发提前声明。

这些风险不能通过降低秘密扫描、放宽 Origin、延长 TTL 或保存重试 body 解决。
