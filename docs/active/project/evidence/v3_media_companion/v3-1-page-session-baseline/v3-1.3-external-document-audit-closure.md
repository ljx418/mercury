# V3-1.3 外部文档审计闭环与实施授权停点

日期：2026-09-17。外审报告：`independent-v3-1.3-document-audit.md`。

## 1. 外审结论

```text
V3-1.3 DOCUMENT CONDITIONAL GO FOR EXPLICIT USER HIGH-RISK IMPLEMENTATION AUTHORIZATION
Fatal = 0
Major = 0
Minor = 2
V3-1.3 implementation = NO-GO pending explicit authorization
```

外审独立确认：19/19 payload SHA-256、V3-1.2 registry 原始绑定、9 名集合 hash、Draft 2020-12 Schema、positive、25/25 cases、8 页 Draw.io 和当前代码事实均一致。

## 2. Minor 处置

- M-1 已绑定到 `V3-1.3-1` 先决验收卡：必须先用真实 Chrome 观测 extension page/service worker 到 loopback POST 的 Origin 字节；缺失或不稳定时停止，禁止接受任意/无 Origin。
- M-2 已绑定到阶段边界：60 秒 lease 只证明 V3-1.3 transport/lifecycle。V3-2 若需要更长生命周期，必须设计同任务受控续租并重新威胁建模，禁止直接延长。

两项均无需在用户授权前改产品代码，也不降低门槛。

## 3. 哈希快照边界

`external-audit-package/` 保留外审读取的 19 payload + 1 manifest 原始快照，不在报告生成后重建。后续 README、stage gate 和本闭环记录属于审计结果索引，不追溯修改已审 payload。

## 4. 自动化开发停止原因

V3-1.3 涉及真实 B站 Cookie 从 Browser 到 Runtime 的秘密传输。虽然文档外审 Fatal=0/Major=0，但此前冻结门禁要求新的、明确的用户高风险授权，且授权范围只能为 `V3-1.3-0..7`。在收到授权前不得创建 endpoint、读取并传输 Cookie、签发真实 lease 或进入 V3-2。

用户批准语句应为：

```text
approved V3-1.3 Browser-to-Runtime credential transport implementation (V3-1.3-0..7 only)
```
