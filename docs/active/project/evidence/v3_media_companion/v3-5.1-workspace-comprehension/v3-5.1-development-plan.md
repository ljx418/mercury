# V3-5.1 Workspace 理解质量与交互开发计划

日期：2026-10-10。状态：`DOCUMENT CANDIDATE / IMPLEMENTATION NO-GO`。

## 1. 目标与非目标

目标是把已能运行的 V3-5 从“有列表输出”提升为可理解、可导航、图文同源的媒体工作台：语义章节、时间尺度、截图节点、播放游标、三层导图、grounded Ask。非目标包括 V4 知识库/RAG、跨视频检索、Agent、视频编辑、替换 B站播放器和默认上传媒体。

## 2. 子阶段

### V3-5.1-0 合同冻结（当前）

- 冻结 schema、20 项 registry/负例、positive fixture、semantic verifier、组件 spike、威胁模型和真实分母。
- 出门：Schema meta/positive PASS，20/20 negative PASS，内部审计 Fatal=0/Major=0，外审 Fatal=0/Major=0，用户显式授权实现。

### V3-5.1-1 语义章节与同源投影

- 新增 `ChapterBoundaryDetector`、`GroundedOutlineSynthesizer`、`WorkspaceProjectionMaterializer`。
- 先用本地确定性特征生成候选，再允许单独授权的 grounded text provider 做标题/层级/摘要；Provider 输出必须重新绑定既有 evidence，不得创造 ID。
- 单元/属性测试：时间范围、父子层级、无环、稳定 hash、Provider 失败回退、未授权 0 network。

### V3-5.1-2 时间线与缩略图

- 新增受控 thumbnail API 和 `VisTimelineRendererAdapter`。
- 显示总时长、章节带、刻度、moment、代表帧和当前游标；wheel/drag/zoom/fit 与键盘等价路径。
- 真实 Chrome 对五类入口中的 chapter/moment/frame 做 seek/readback。

### V3-5.1-3 图文大纲

- 实现 sticky current chapter、章节目录、折叠、关键点、代表帧、证据标签和时间入口。
- frame/OCR/vision/transcript 明确分型；缺 frame 显示文本证据态，不用占位图。

### V3-5.1-4 导图

- 新增 `MediaMindmapProjectionV2` 与 `MarkmapRendererAdapter`。
- root/chapter/key-point 三层以上，pan/zoom/collapse/fit；同步提供 ARIA tree 键盘视图。

### V3-5.1-5 Ask V2

- 新增 query classification、chapter/time/type index、cross-chapter retrieval 和逐 block citations。
- 固定 12 问；证据不足拒答；visual 问题必须使用视觉 evidence。

### V3-5.1-6 整合与低资源

- `PlaybackCursorController` 在当前 source identity 下同步当前时间和章节；切页/分P/关闭 Workspace 立即清理。
- 四视口、Axe、键盘、drag/wheel、CSP、bundle、内存和主线程阻塞验收。

### V3-5.1-7 新鲜真实出门

- 3 个真实 B站视频在单次 fresh run 重新采集和生成，禁止复用 BiliNote 输出。
- 自动分母全绿后，仅做一次最小人类体验复核；独立出门审计 Fatal=0/Major=0 后放行 V3-6。

## 3. 每阶段固定流程

每个子阶段在代码前建立独立 acceptance/preimplementation audit；完成后执行 unit/integration/真实 Chrome、PRD review、false-green audit 和 exit audit。出现跨合同改动、云端权限扩大、真实 seek 假绿、质量分母缩小或重大体验偏差时立即停止并回到计划。

## 4. 交付文件

- Runtime comprehension domain、versioned API 和 migration。
- Extension timeline/outline/mindmap/playback adapter 与组件测试。
- 3-video benchmark、12-question benchmark、seek observations、四视口截图和 Axe/keyboard/performance evidence。
- 每阶段开发/验收/PRD/审计记录；最终外部审计包。

## 5. 依赖顺序

`v2 evidence/task -> V3-5.1-1 semantic projection -> 5.1-2/3/4 renderers -> 5.1-5 Ask -> 5.1-6 integration -> 5.1-7 exit -> V3-6`。UI adapter 不可先于同源 projection 进入生产；V3-6 不得继续使用旧 fixed-window projection 作为正向基线。
