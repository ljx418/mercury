# V3-5.1 三视频生产候选续建计划

日期：2026-10-10  
状态：`AUTHORIZED / IMPLEMENTATION PENDING`

## 1. 目标与唯一缺口

在一个全新的 run 内，对 `fresh-probe/frozen-sample-registry.json` 固定的三个真实 B 站视频逐一完成：完整 SenseVoice ASR、全时域最多 8 个确定性选帧、本地 OCR、受治理 MiniMax 画面描述、章节/时间线/导图、本地证据问答和浏览器交互验证。最终形成三个不可拼接的生产候选及一个总清单。

本阶段不新增产品规格，不上传原视频、原音频、转写正文或 OCR 文本；云端仅接收用户已授权的固定选帧。Cookie 与 API key 只从用户提供的私有文件读入进程内存，不写公开证据。

## 2. 实施顺序

1. **PC-0 合同冻结**：固定三样本、工具哈希、模型哈希、V3-5.1 schema、20 个负例和公开/私有边界。
2. **PC-1 Runner**：扩展全文 ASR runner，在私有转写被清理前，以同 task/source/segment 输入生产物化器。
3. **PC-2 视觉链**：为每视频重新签发短期 Cookie lease；按完整时长分布取帧，执行本地 OCR 和 MiniMax-M3 画面描述；每视频最多 8 次图片调用。
4. **PC-3 投影与问答**：生成同 outlineId 的章节、时间线、导图；运行 6 factual、2 visual、2 cross-chapter、2 insufficient 问题。
5. **PC-4 浏览器验收**：在真实 Chrome 中加载同一候选，执行五类入口各两次 seek、四类时间线操作、导图键盘流程、四视口和 Axe。
6. **PC-5 封存**：校验三个 candidate 的 schema/semantic、清理状态与秘密扫描，写入总 manifest；不保留下载音视频或临时取帧。
7. **PC-6 PRD 检视**：逐项输出 A01..A20，不允许 N/A；任何 Major 返回本计划修订。
8. **PC-7 人工最小复核准备**：只在机器门槛全绿后生成固定 bundle 的复核页面，不自动代签人类判断。

## 3. 实现边界

- 允许修改 `services/local-runtime/scripts/` 下 V3 验收 runner，以及为 runner 提取的纯转换模块和测试。
- 优先复用 `MediaProductMaterializer`、`MediaComprehensionService`、`MediaAskService`、`VisionProviderStore` 与现有 Chrome 工作台，不另建平行产品实现。
- 不改用户已验收的 Cookie/Runtime 安全模型，不降低 SenseVoice 全文覆盖率，不启用 grounded-text cloud。
- 生产候选只保留派生 JSON、哈希、公开缩略图审查引用和机器观察；私有原媒体、音频、Cookie、key、stderr 与临时帧不得进入仓库。

## 4. 停止条件

- 三视频任一无法完成全文 ASR、视觉选帧或同源投影。
- MiniMax 调用需要扩大到原媒体、音频、转写或 OCR 上传。
- 浏览器交互只能通过 DOM 直调或伪造 seek readback 通过。
- schema/semantic、Axe、秘密扫描或清理任一出现 Fatal/Major。
- 需要缩小 A01..A20、跨 run 拼接或复用旧候选。
