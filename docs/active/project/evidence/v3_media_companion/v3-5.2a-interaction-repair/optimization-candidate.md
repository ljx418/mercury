# V3-5.2a 实时交互与媒体工作台优化候选

日期：2026-10-11。状态：`IMPLEMENTED CANDIDATE / MACHINE PASS / HUMAN UX PENDING`。

## 1. 用户问题与根因

1. Chat 已具备 SSE `response.delta`，但消息容器没有随新增 token 自动跟随；首次等待阶段也没有立即进入对话状态流，导致真实流式传输在视觉上表现为静止。
2. 页面上下文、媒体授权、Runtime、采集状态和知识草稿同时以卡片占据 Chat 首屏，主对话被挤到下方。
3. Media 证据页只有 Esc 恢复协议，没有始终可见的返回命令；顶部品牌链接又只能回任务列表，恢复路径不够明确。
4. 高质量转换和视频问答是同步长请求，界面只有静态按钮文案，用户无法判断请求是否仍在运行。
5. 大纲目录只显示标题，章节论点必须逐项展开；时间线虽支持拖动和缩放，但缺少连续的章节截图导航。

## 2. 已实现候选

- Chat 提交后立即显示“理解问题 → 准备上下文 → 等待模型 → 正在回答”；首 token 到达时状态切换为 streaming。
- 对话默认跟随新增 token；用户主动上滚超过 72px 后停止抢滚动，回到底部后恢复跟随。
- 页面、媒体、Runtime 与知识草稿收纳到顶部状态抽屉；默认只显示呼吸状态点、当前阶段和页面标题。
- Media 顶部增加确定性返回命令；证据页增加“返回证据来源”，无来源绑定时回退到当前任务大纲。
- 高质量转换和媒体问答显示真实已等待秒数，不伪造百分比。
- 大纲目录同时显示章节标题与论点；时间线增加横向章节截图导航、当前章节高亮和直接视频反跳。

## 3. 开源方案核查

| 方案 | 优点 | 架构成本 | 当前决定 |
|---|---|---|---|
| `visjs/vis-timeline`（MIT/Apache-2.0） | 原生拖动、滚轮缩放、范围和分组成熟 | 新依赖、需做媒体毫秒坐标和无障碍适配 | V3-5.3 绘制层候选；不替换证据模型 |
| `xyflow/React Flow`（MIT） | 节点、边、缩放、平移和自定义节点成熟 | bundle 与键盘语义成本较高 | V3-5.3 导图绘制层候选 |
| `markmap`（MIT） | Markdown 到导图成本低 | 无法自然承载证据类型、截图、反跳回执 | 仅用于导出/只读降级，不做主交互 |
| 本地 `bilinote` / 上游 BiliNote | 字幕优先、ASR 兜底、章节总结、时间戳贯穿体验 | 直接迁移会破坏 Navia Runtime、证据与安全边界 | 复用信息组织方法，不复制状态/密钥架构 |

主数据仍为 `MediaComprehensionProjection`。第三方库只能消费章节、moment、evidence 和 seek callback，不得重新生成事实、绕过 Runtime 或改变失败语义。

## 4. 下一阶段开发顺序

## 5. 出门门槛

- Chat 首次提交后 300ms 内出现可见状态；每个 `response.delta` 可增量显示，不等待完整回答。
- 用户停留底部时自动跟随；主动上滚后不得抢滚动。
- 默认 Chat 首屏不得展开连接、授权、任务和上下文卡片。
- Media 所有子路由都有可见返回路径；返回后页面可继续键盘和鼠标交互。
- 大纲首屏可看见总论与章节论点；时间线可见章节截图、时间范围和播放器反跳。
- 第三方 renderer 故障时降级到当前 HTML renderer，不丢证据或反跳能力。
