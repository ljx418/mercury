# C4 — the MiniMax candidate shape and the bounded repair

## 1. What the investigation found

The MiniMax adapter sends a chat completion whose prompt carries a **soft**
`outputSchema`. The independent validator requires an **exact** object. A
model answer that is structurally wrong (a wrong key set, a wrong chapter
count, a wrong chapter field set, a wrong relation enum) was therefore
discovered only by the independent validator — after the answer had been
handed to it — and the rejection was final: the chapter failures are not
repairable by the frozen repair route, which is limited to the brief failures.

The correction does NOT relax the frozen rules. The adapter now **enforces the
frozen shape itself**, before the candidate leaves the adapter, and regenerates
a malformed answer with the SAME selected Provider inside a hard request
bound.

## 2. The enforced shape

| Level | The frozen shape |
|---|---|
| the top level | exactly `brief`, `claims`, `chapters`, `unresolvedEvidenceConflict` |
| `brief` | exactly `text`, `evidenceIds` |
| a claim | exactly `text`, `evidenceIds` |
| a chapter | exactly `title`, `thesis`, `evidenceIds`, `relationToPrevious` |
| the chapter count | 2..12 |
| the claim count | 2..8 |
| the relation enum | `opening`, `continuation`, `contrast`, `cause_effect`, `example`, `conclusion` |

The adapter's check is a **refusal**, never an acceptance: the independent
validator stays authoritative. The case `the independent validator stays
authoritative` proves it — a candidate with a valid shape but an unknown
evidence id is still refused with `V3510B_EVIDENCE_UNCLOSED`.

## 3. The bounded regeneration

| Situation | What the adapter does |
|---|---|
| a malformed shape | regenerates with the SHAPE rules and the redacted temporal index, by the SAME Provider |
| a temporal-anchor violation | regenerates with the temporal contract and the redacted temporal index, by the SAME Provider |
| the hard request bound is reached | raises `V352_SYNTHESIS_RESPONSE_INVALID` → the frozen `V3510B_PROVIDER_RESPONSE_INVALID`; nothing is published |

The bound is `_STAGE_B_MAX_REQUESTS = 8` per adapter instance, it is exposed
as `provider.request_bound` and it is asserted by the case `the request bound is
hard and exposed`. The receipt's `request_count` reports the requests that
were really made.

Nothing is normalized locally: no chapter is created, deleted, merged or
reordered, no evidence id is substituted, and an invalid model answer never
becomes a local deterministic success. A persistent invalid output keeps the
existing frozen failure code and publishes nothing.

## 4. The redacted temporal index

The repair request carries a temporal index with COUNTS and TIMESTAMPS only:

```json
{
  "evidenceCount": 6,
  "distinctStartCount": 5,
  "duplicateStartGroupCount": 1,
  "maximumDuplicateStartMultiplicity": 2,
  "firstStartMs": 0,
  "lastStartMs": 40000,
  "minimumChapterCount": 2,
  "maximumChapterCount": 12,
  "strictlyIncreasingAnchorsRequired": true
}
```

No text, no title and no evidence id is added by the index. The case `the
repair request carries the redacted temporal index` asserts that the serialized
index contains neither the transcript text nor an evidence id.

## 5. The fake-client matrix

| Case | First answer | Next answer | Outcome |
|---|---|---|---|
| `a malformed first candidate is regenerated by the same provider` | a wrong top-level shape | a valid candidate | accepted, two candidate requests, the regeneration request carries the shape rules and NOT the rejected text |
| `a temporal invalid first candidate is regenerated` | equal chapter anchors | a valid candidate | accepted, the repair request carries the temporal contract |
| `a persistently malformed candidate exhausts the bound` | wrong shape, twelve times | — | `V352_SYNTHESIS_RESPONSE_INVALID`, the requests never exceed the bound |
| `persistently duplicated anchors fail closed` | equal anchors, twelve times | — | `V352_SYNTHESIS_RESPONSE_INVALID`, the requests never exceed the bound |
| `the receipt reports the request count and the digests` | a valid candidate | — | the request count, the outbound digest, the response digest and the attempt id are recorded |
| `the adapter records the redacted stage diagnostics` | a wrong shape | a valid candidate | the stage diagnostics are recorded and carry no text and no id |

## 6. The endpoint feature

The adapter does **not** assume that the endpoint supports a JSON-schema
`response_format`. The request is unchanged in that respect: the shape is
requested through the prompt and **enforced locally** after the answer, with a
fail-closed path. No new endpoint class and no new Provider were added.

## 7. The C3 consequence

The shape and the anchor facts of every rejected candidate are now available as
a redacted diagnostic (see `05-c3-diagnostic-samples.json`), so a future
visible run can tell a malformed model answer from an evidence catalog that
cannot support two strictly increasing anchors — without keeping any text.
