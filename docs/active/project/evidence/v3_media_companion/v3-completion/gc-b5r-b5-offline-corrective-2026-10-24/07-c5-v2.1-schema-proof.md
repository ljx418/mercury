# C5 — the receipt-extras fix and the frozen V2.1 schema

## 1. What was retained

The comprehension service reads the Provider's receipt extras — `attemptId`,
`requestSha256`, `responseSha256`, `latencyMs`, `finishReason`,
`endpointClass` and `structureMode` — **after** the Provider request, and
again **after** a bounded repair. Before the correction the extras were read
*before* the request, so the published derivative carried an empty
`attemptId`, `requestSha256` and `responseSha256` and did not satisfy the
frozen V2.1 schema.

## 2. The schema gate

`tests/test_v3_gc_b5r_corrective_authority.py` validates the **published
derivative** against the frozen schema
`docs/active/project/contracts/v3_media_grounded_comprehension_v2_1.schema.json`:

| Case | What it proves |
|---|---|
| `the published derivative satisfies the frozen v2_1 schema` | the initial route publishes a schema-valid derivative: the `attemptId` matches the frozen pattern and the two digests are 64 hex characters |
| `the repair path also publishes a schema valid derivative` | the REPAIR route publishes a schema-valid derivative too, and the repair ran exactly once (it is bounded) |

The schema itself was NOT modified, and the validator was NOT weakened: its
existing negative cases still refuse an unknown evidence id, an out-of-range
chapter count, a malformed chapter field set and a non-increasing chapter
start.

## 3. The frozen rules are unchanged

| Rule | State |
|---|---|
| the chapter starts remain strictly increasing | unchanged |
| the chapter count remains 2..12 | unchanged |
| the chapter fields remain exact | unchanged |
| every evidence binding remains closed | unchanged |
| the receipt extras are read after the request and after the repair | retained and extended |
| the published derivative satisfies the frozen schema | proven by two cases |

## 4. What the previous run's evidence still shows

The three derivatives published by the rejected real run carry the EMPTY
receipt extras, because that run predates the correction. They are historical
evidence: this batch does not edit them. A future visible run must re-publish
the derivatives to produce schema-valid evidence. That is recorded as a
residual risk in `09-prd-coverage-and-risks.md`.
