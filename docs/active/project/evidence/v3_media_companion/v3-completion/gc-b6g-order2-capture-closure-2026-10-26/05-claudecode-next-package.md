# ClaudeCode Next Package

## Objective

Execute, do not redesign, one fresh GC-B6B six-source candidate and the frozen
blind review only if the machine gate is positive. Stop at the Codex checkpoint.

## Preconditions

- Obtain a separate explicit authorization for the six-source visible batch,
  Cookie use, owned muted Chrome instances, isolated Runtime instances,
  downloads, SenseVoice, frame/OCR/vision calls, and private review storage.
- Lock the active registry digest/order/reserves, the current B6 harness file
  hashes, the rubric hash, and the prompt hash before any external action.
- Use a new authorization id, run id, stage root, evidence root, and 0700
  private root. Never reuse any order-2 confirmation root or receipt.
- Run production preflight and require every zero-action check to pass.

## Execution

1. Run exactly the six frozen primary sources in registry order. Do not use a
   reserve, substitute a BVID, retry a source, or merge historical rows.
2. For every source require the real V2.1 publication oracle, exact Provider
   request accounting, zero-upload assertions, closed cleanup, and a private
   bundle that passes production re-read and validation.
3. Stop immediately on the runner's frozen fatal stop condition. Preserve the
   full same-shape audit set for complete, limited, blocked, and failed rows.
4. Require six fresh complete rows and a positive B6 machine authority before
   generating any blind projection. A missing or invalid bundle is not a
   reviewable row.
5. If the machine gate is positive, use the precommitted review order and two
   independent sessions. Keep Provider/model/endpoint identity blind. Execute
   the frozen sentinel at both committed positions and reject reversal,
   changed claims, same-session reuse, or rubric/prompt drift.
6. Apply the frozen four-axis threshold (each axis at least 4), require zero
   critical errors, and publish only the aggregate decision and privacy-safe
   receipts. Do not place derivative text, images, paths, secrets, Cookie
   material, or Provider responses in public evidence.

## Mandatory Verification

- Re-run the focused B6 bundle/capture tests and the complete Stage B offline
  suite before the visible batch.
- After execution, re-read every private bundle with production
  `readReviewBundle()` and `validateReviewBundle()` and verify its manifest.
- Reconcile the append-only action ledger with every source receipt.
- Prove no owned process, port, profile, scratch root, or staging directory
  remains. Do not kill or count unrelated processes.
- Generate the public evidence manifest last and verify it.

## Stop Conditions

- Any lock or preflight failure: stop before Chrome/Cookie/Provider action.
- Any source failure or capture failure: follow the frozen aggregate policy;
  never fill the row from an older run.
- Negative machine gate: do not perform blind review.
- Any privacy, authority, process-leak, manifest, identity, request-accounting,
  sentinel, rubric, or prompt defect: fail closed and return to Codex.

## Required Handoff

Return changed files (normally none outside evidence), contract changes or
`none`, command exits, six source dispositions, machine-gate result, review and
sentinel result if run, action ledger totals, privacy scan, cleanup audit, PRD
coverage, remaining risks, and a final payload manifest. Do not announce B6,
Stage B, or V3 pass; Codex makes the checkpoint decision.
