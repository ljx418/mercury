# WP0 R7 后续交接

## 当前坐标

`V3 completion / WP0 / R7 constrained closeout complete`。

WP0/P0 输入链与 capture 安全工作包可以受限关闭。不得再重复运行 R0-R7 或重新争论历史 G2 结果，除非公共合同、安全边界或候选摘要发生变化。

## 下一开发顺序

1. **WP-A 媒体依赖就绪**：让 yt-dlp、ffmpeg、SenseVoice 的状态、安装、固定摘要、空间、自检、失败分类、设置页和任务清理成为正式产品体验。
2. **WP-B 显式本地视频导入**：先做原型和文档冻结，再实现用户手势单文件选择、受认证导入、进度/取消、大小/磁盘/损坏/重启矩阵和 SourceAuthority 仲裁。
3. **WP-C tabCapture 重新资格化（可选）**：只有 WP-A/WP-B 仍无法覆盖关键场景且收益高于维护成本时启动；否则继续 default-off，后续可移除用户入口但保留历史证据。

## WP-A 出门条件

- 不静默下载任意 URL；依赖来源与摘要固定。
- 设置页明确显示缺失、下载、校验、自检、ready、失败和清理状态。
- 自动路径成功时不增加用户操作；失败时给出可执行下一步。
- 模型/工具持久化到 Windows 项目管理目录或系统受控目录，不依赖易回收的 WSL 虚拟磁盘。
- 无秘密、媒体或私有路径进入公开证据。

## WP-B 开发前门禁

必须先补齐 PRD、目标架构、API/schema、SourceAuthority、隐私/清理、失败码与验收矩阵。不得直接在 R7 或 relay v11 中追加文件上传端点；不得默认扫描本地目录。

## 不再重复的工作

- 不为当前 WP0 再做 ClaudeCode 文档外审。
- 不因单文件纠偏重复全量外审或可见 Chrome。
- 不用下载路线通过替代 capture 历史分母，也不用 capture 历史实现阻塞 WP-A/WP-B。
