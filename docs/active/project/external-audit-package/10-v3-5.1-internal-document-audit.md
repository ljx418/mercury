# V3-5.1 Workspace 理解优化内部文档审查

日期：2026-10-10。范围：PRD、架构增量、开发/验收计划、组件 spike、合同、fixtures、语义校验器与威胁模型。未运行产品代码或真实 Chrome。

## 1. 第一轮：规格与实现映射

结论：`Fatal=0 / Major=2 / Minor=2`。

- 用户反馈的六项缺口已逐项落盘：时间轴交互、语义章节、图文证据、导图层级、Ask 质量、播放双向同步。
- 计划没有废弃 V3-1..5；新阶段插入 V3-5 与 V3-6 之间，复用 task/evidence/seek/权限合同。
- Major 1：初稿只描述 UI 组件，没有版本化的跨投影合同，可能继续以三套列表数据制造漂移。
- Major 2：selected-frame cloud vision 授权可能被错误复用为 transcript/OCR 文本授权。
- Minor 1：第三方组件的 npm 包体和生产 bundle 不是同一指标。
- Minor 2：用户报告人工流程通过，但仓内 H01..H10 正式 submission 仍 pending，不能混写。

## 2. 修订闭环

1. 新增 `v3-media-workspace-comprehension/v1`，将 task、authorization、evidence、outline、timeline、mindmap、Ask benchmark、seek 和 UI/resource observation 绑定为一个候选信封。
2. 新增 20 项 registry、20 个 negative cases 和 semantic verifier，覆盖身份、章节、证据、树、问答、seek、云 scope、原媒体上传和 CSP。
3. 云端文本 scope 默认 disabled，与最多 8 帧的云视觉 scope 分离；未授权时 provider/model/hash 必为空，Ask 只允许本地模式。
4. `vis-timeline`/`markmap-view` 只做可替换 adapter；生产 bundle delta、Axe、CSP 和低资源在实现期重新测量。
5. 明确区分“用户报告流程可完成”与“正式 H submission 尚未签署”；V3-5.1 最小体验复核不伪造旧 H 结果。

## 3. 第二轮：防假绿与边界

结论：`Fatal=0 / Major=0 / Minor=3`。

- Schema meta 与 positive instance PASS；positive semantic errors=0；20/20 negative 被预期 failure code 或更强 schema gate 拒绝。
- 固定分母不可 N/A：3 个真实视频、一个 >=30 分钟、3..12 章节、>=8 moments、12 问、>=10 seek、四视口、8 GiB/no-GPU。
- BiliNote 只作为体验参照；禁止其输出进入 Navia production evidence。
- 旧 outline v2 保持只读，V3-6 明确依赖 V3-5.1 新投影，不存在向后静默冒充。
- V4 知识/RAG/Agent、跨视频问答仍排除。
- Minor 1：3 个真实视频 URL/CID 需在 V3-5.1-1 前通过真实 probe 冻结，以防提前固定失效样本。
- Minor 2：最终 DOM/heap/bundle 数字只能由 production build + >=30 分钟视频冻结；当前只冻结上限原则。
- Minor 3：第三方 renderer 的键盘/Axe 结论必须由实现期真实 Chrome 证明，文档审查不能替代。

## 4. PRD 与架构判断

文档能支撑 V3-5.1-0..7 的顺序实施，没有偏离 V3 “当前视频理解与交互”的目标。关键数据流保持单向：真实 evidence -> 同源投影 -> renderer adapter -> governed seek/read；前端不直连模型，renderer 不成为事实源。开发完成后能够直接解决用户已报告的体验缺口，但在真实样本和最小人类复核完成前不得宣称质量达到 BiliNote 或 V3 最终完成。

## 5. 决定

`V3-5.1 DOCUMENT CANDIDATE: READY FOR EXTERNAL DOCUMENT AUDIT`。这不是实现授权。外部审查 Fatal=0/Major=0 且用户另行明确授权后，才可进入 V3-5.1-1 产品代码；V3-6/V3-7 继续 BLOCKED。
