# Navia 项目方法与经验

## 1. 单一阶段循环

每个 V 阶段遵循同一闭环：

```text
原型开发
-> 原型审查
-> 阶段性原型优化
-> 文档迭代（体验对齐/架构/计划/内审/必要外审）
-> 分工作包实现与逐包 checkpoint
-> 阶段 closeout（真实 E2E/可视化报告/人工体验/Git 同步）
```

原型和文档通过不代表代码已实现；自动化测试通过不代表内容体验通过；人类体验通过也不能
代替机器安全、恢复、隐私和一致性门槛。

## 2. 固定职责

- **Codex**：维护 PRD、架构、合同、计划、验收标准、交接包、证据抽查和 PASS/NO-GO。
- **Codex 独立 Agent**：只读复算文档或实施候选；不参与被审代码实现。
- **ClaudeCode CLI**：一次只实现一个已冻结工作包，负责高 token 源码追踪、编码、自验证、
  长测试和证据 handoff；不能签署自己的阶段 PASS。
- **用户**：只处理秘密使用、可见浏览器、平台权限等高风险授权，以及最终体验判断。

每次交给 ClaudeCode 的提示词必须完整可复制，包含当前门禁、范围、必读文件、目标、禁止项、
验证门槛、证据和停止条件。不得让用户自行拼接多个历史提示词。

## 3. 三层验证

1. **实现内循环**：每次修改只跑定向测试、类型检查和必要静态门禁。
2. **工作包 checkpoint**：工作包完整后只做一次相关子树回归、受影响 verifier、PRD 映射和
   Codex 复核；一次汇总全部问题。
3. **阶段 closeout**：阶段全部工作包完成后，才运行全量 E2E、真实数据、可视化报告、独立
   实施审查、人工体验和 Git 同步。

文档外审用于规格冻结，不用于每次小修。重复跑同一审计不会增加事实覆盖，只会增加 token、
时间和证据漂移。

## 4. 防止虚假通过

每项关键义务必须具有：

```text
规格义务 -> 生产调用路径 -> 测试驱动 -> 明确 oracle -> 负例 -> terminal/cleanup
```

经验规则：

- 测试名、字符串存在、固定 JSON、总测试数和 exit 0 不能单独证明行为成立。
- composition 必须驱动真实 owner/router/adapter/state machine；只允许替换浏览器或网络原语。
- 上限测试必须验证 equal 与 one-over，不能先撞到另一个更小限制。
- deadline 必须在没有后续输入时由时钟主动触发。
- fail-closed 同时验证固定错误码、未写入/未入队、producer/consumer 停止、terminal、marker
  和临时资源清理。
- 真实数据 run 不跨 run 拼接，不用旧结果补新候选，不让人类代做机器可验证事项。

## 5. 冻结材料与活动源码

- 合同、source inventory、实现 scope 分开表达；实现文件正常变化不能导致 verifier 跳过整文件
  后把 AST 缺失误报成产品缺陷。
- 哈希漂移先分类为实现缺陷、未授权漂移或冻结证据过期。
- 只有工作包结构稳定后由 Codex 一次性重冻结；不在每轮纠偏重复重冻结。
- 历史失败证据保留，不修改为通过；新候选并列落盘。

## 6. 工作树与安全

- 默认工作树很脏；禁止 reset、clean、checkout、revert 用户改动。
- 修改范围必须和当前工作包一一对应；Git 提交只在阶段收口且范围可解释时执行。
- 自动化测试不得播放声音；真实 Chrome 必须显式 `--mute-audio`。
- Cookie、API key、ticket、streamId、PCM、原始媒体和私有绝对路径不能进入公开证据。
- 只清理由本轮创建且能证明 ownership 的进程、profile、端口和临时件。

## 7. 中断与恢复

- 中断后先读最新 checkpoint/handoff，不从聊天记忆猜测状态。
- 429/529：停止重试，记录 changed files、最后完整动作、命令/退出码、资源和 nextSafeAction。
- 422：区分工具输入错误与产品 Provider 错误；禁止无变化原样重试。
- 每次停止必须写明当前门禁、未完成项、下一安全动作和“自动化开发停止原因”。
- 新窗口先报告项目坐标、文档覆盖度和当前唯一工作包，再决定是否实施。

## 8. 已获得的核心教训

1. 同一问题反复外审不会替代生产 composition；先扩展观察面，再做一次集中 checkpoint。
2. 实现者自报的“已重置”“已清理”“恰好一次”必须与真实代码位置和生命周期一致。
3. 单次 happy path 不证明第二轮可用；涉及 session/Port/marker 的能力必须测试跨轮隔离。
4. 测试替身越过真实入口会制造 false green，例如直接调用 Transport 不能证明 Port 接线正确。
5. 阶段状态必须使用 `PASS / NO-GO / AWAITING CHECKPOINT / NOT_IMPLEMENTED`，不能用“基本完成”
   混淆已实现、受限和规划状态。
