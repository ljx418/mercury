# V3 用户体验规格与反退化门槛

## 1. 产品入口

- 一级产品域只有 `Chat` 与 `Know`；`Settings` 是辅助入口。
- Agent/多 Agent 不进入 V3 生产导航。
- Runtime 由用户通过桌面“Navia 本机伴侣”显式启动；扩展不得静默拉起进程，也不承诺随浏览器关闭自动退出。

## 2. 首次与日常路径

首次使用：安装扩展与本机伴侣一次，启动伴侣，完成一次配对与一次 B站窄域权限，按需保存 Provider 密钥到系统凭据库。

日常使用：

1. 打开页面和 Navia。
2. 系统自动识别当前普通网页或 B站视频，不要求用户依次点击“读取/提交/总结”。
3. 用户点击一个主动作“分析当前页/视频”。
4. 顶部状态只显示最新任务、已用时间、当前步骤和明确恢复动作；内部步骤折叠。
5. 转写可先显示为“转写预览”，完成 grounded projection 后自动切换到可用大纲；不得把预览冒充全片概览。
6. 用户查看概览、大纲、时间线、概念图，点击证据回到视频时间点。
7. 用户可提问、生成导出内容或提取 KnowledgeDraft；只有确认后保存到 Know。

## 3. 各视图必须不同

### 概览

- `VIDEO BRIEF` 不超过 100 个中文字符，说明主题、关注焦点和主要结论，不复制首分钟转写。
- 展示全片结构、主要表达、关键依据及证据充分性。
- 转写按说话人/时间戳折叠显示，属于原始参考，不占据主要视觉层级。

### 大纲

- 用章节层级表达全片叙事或论证结构，章节覆盖视频全时长且时间单调。
- 每个重要章节至少展示可用的视频截图/帧证据；无证据时明确标注，不补造截图。
- 不再混入“知识长文/图文笔记/深度专栏”；这些属于导出。

### 时间线

- 横轴使用视频相对时间 `mm:ss/hh:mm:ss`，禁止显示国际日期时间。
- 支持鼠标滚轮横移、拖动、键盘和焦点操作；截图多时可堆叠，获焦后展开。
- 点击节点必须 seek 到对应视频时间，并返回可观察 receipt；失败不得静默。

### 概念图

- 节点来自视频中的概念、实体、论点和因果/对比/组成关系，不固定为“主题-章节-关键点”。
- 可拖动节点、保存布局、缩放和平移；关系边端点必须存在且能追溯证据。
- 图形库只负责布局交互，不能生成无证据概念。

### 导出

- 至少五种 prompt-distinct 风格，例如视频大纲、知识长文、图文笔记、深度专栏、平台短帖。
- 用户可选覆盖范围、候选图片和内容密度；每次生成独立 artifact，显示来源帧与生成状态。
- AI 生成图若未来启用，必须 opt-in 且与视频真实帧明显区分。

## 4. Chat 与 Know

- Chat 提供当前上下文问答、页面/视频摘要、证据反跳和知识提取。
- 等待模型时必须实时显示连接、首片段、持续时间和失败原因，不显示空白 `...` 卡住。
- Provider 设置重载后仍由 Runtime 凭据库和持久配置恢复，扩展不得保存明文密钥。
- Know 只展示真实本地 Item，支持编辑、标签、自定义字段、排序、人工 aging、归档、普通删除和来源反跳。
- 删除不得称为 Durable Forget；Query/Graph/自动老化属于 V4。

## 5. 反退化验收

- 已有结构化/详细结果风格不得因 UI 重构丢失内容。
- 大纲、时间线、概念图不能只是同一转写列表换皮。
- 任何完成态必须停止黄色呼吸灯和“正在分析”；失败/超时才展开详情。
- 页面返回、关闭弹窗、清空聊天、新聊天必须真实改变状态并可键盘操作。
- 360/420/768/1280 视口不得截断主要命令或产生不可滚动区域。

## 6. 状态披露与恢复体验

| 系统事实 | 顶层用户文案 | 主动作 | 详情 |
|---|---|---|---|
| Runtime 未启动 | 本机伴侣未连接 | 查看启动方法/重试 | 端口与安全会话诊断折叠 |
| 正在获取/转写 | 正在处理当前视频 + 已用时间 | 取消 | 最新步骤、`lastProgressAt`、route |
| 超过 10 秒无变化 | 仍在处理，最近进展于… | 继续等待/取消 | 不伪造百分比，不立即判失败 |
| blocked | 需要处理后才能继续 | 按原因授权/配置/重试 | 精确 FailureCode 与影响 |
| degraded | 已生成受限结果 | 查看结果/重新分析 | 缺失字幕、截图或 Provider 的范围 |
| ready | 分析完成 | 查看视频大纲 | 停止黄色呼吸灯和 busy 计时 |
| cancelled/failed | 已停止/处理失败 | 重新分析 | 清理状态与可恢复条件 |

完成态必须自动刷新主视图，不要求用户通过打开另一个路由才看到结果。刷新浏览器或重启 Runtime 后，UI 必须先按 `sourceIdentity` 恢复权威 task/revision，再恢复对应视图。

## 7. 最小用户路径与操作预算

### B站视频

1. 用户启动本机伴侣并打开已授权 B站视频。
2. 打开 Navia，只点击一次“分析当前视频”。
3. 在同一界面看到步骤、计时器和可取消动作；无需手工“读取页面/提交上下文”。
4. 转写预览可先出现；发布后自动进入概览，并可切换大纲、时间线、概念图和导出。
5. 点击截图/证据跳回视频时间点；失败显示可观察 receipt。
6. 在 Chat 提问或提取知识，确认后才保存到 Know。

### 普通网页

1. 打开网页与 Navia。
2. 点击“总结当前页”或直接提问；系统自动构造页面上下文。
3. 用户可查看引用、生成导图或提取 KnowledgeDraft。

正常日常路径中，除主动作与明确的知识确认外，不应出现多次授权、连接、提交上下文或内部任务管理按钮。

## 8. 人工验收重点

- 人类只判断内容价值、信息层级、交互负担和视觉稳定性，不承担听写或机器合同复算。
- 六个固定视频中分别检查短/长内容、字幕/ASR、截图证据、章节覆盖、seek、问答和导出。
- 对同一视频在两个页签和 Side Panel/Workspace 间切换，必须看到同一 task/revision，不重复分析。
- 故意断开 Runtime、刷新页面、取消和重试，必须有明确恢复动作且无旧任务晚到覆盖。

## 9. 导出与 Chat/Know 细化

- 导出默认使用当前同 task/revision 的 grounded projection，不能把旧任务、另一 Provider 或另一个视频的结果拼接进来。
- 视频大纲、知识长文、图文笔记、深度专栏、平台短帖必须使用独立模板或提示词，输出结构和信息密度可观察地区分，而不是只替换标题。
- 用户在生成前选择范围、篇幅、引用密度和候选真实截图；生成中可取消，失败可重试。每次生成独立 artifact/receipt，不覆盖源 projection，也不自动保存到 Know。
- Chat 用户消息提交后 1 秒内出现“已接收/正在处理”反馈；流式或分段响应显示真实阶段，不得长时间停在空白 `...`。
- 新聊天立即切换为空白会话；清空全部、删除单条必须真实修改持久状态，并提供必要确认或撤销。
- Provider 密钥只保存到系统凭据库，扩展刷新后配置仍可用但不能读回明文。MiniMax 保持默认；DeepSeek 只在用户手动选择后生效，首次使用不得诱导特定供应商。
- Chat 生成 KnowledgeDraft；用户可预览、编辑、取消或确认。取消后 Know 中新增条目数必须为 0。
- Know 的 KnowledgeItem 支持真实编辑、排序、归档、删除和来源反跳；V4 Query/Graph/Durable Forget 不在 V3 中显示为已实现。

## 10. 最小最终验收路径

1. 启动本机伴侣，打开固定 B站视频和 Navia。
2. 只点击一次“分析当前视频”，观察 10 秒内状态、计时和当前步骤持续更新。
3. 转写预览出现后等待 grounded 结果；确认 UI 自动进入 ready/degraded 并停止 busy。
4. 分别检查概览、大纲、时间线、概念图的信息结构；点击截图或节点并确认视频 seek receipt。
5. 在 Chat 提一个事实问题和一个跨章节问题，检查首反馈、答案、证据和失败披露。
6. 生成两种不同导出风格，确认结构差异、图片选择和取消/重试可用。
7. 提取 KnowledgeDraft，先取消一次，再确认一次；到 Know 检查条目、来源与 Runtime 重启后一致性。

该路径只用于最终候选的人类体验，不替代自动化 secret、cleanup、schema、同 revision 和内容质量复算。
